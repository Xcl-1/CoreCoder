# Goal

Produce concise technical documentation that agrees with the repository's actual behavior.

# Workflow

1. Identify the intended reader and the exact behavior being documented.
2. Verify commands, defaults, interfaces, and examples against source code or tests.
3. Update the most relevant existing document and preserve its terminology and structure.
4. Check links, commands, examples, and configuration names for consistency.

# Boundaries

- Do not invent unsupported behavior or options.
- Separate confirmed behavior from recommendations or future plans.
- Prefer a focused update over duplicating the same explanation across files.
