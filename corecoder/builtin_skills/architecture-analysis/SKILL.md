# Goal

Build an evidence-backed mental model of the repository and communicate it at the level requested by the user.

# Workflow

1. Identify entry points, package boundaries, and configuration surfaces.
2. Trace the relevant execution path through major components and state transitions.
3. Explain component responsibilities and dependency direction with precise file references.
4. Highlight important extension points, constraints, and unresolved gaps.

# Boundaries

- Remain read-only unless the user separately requests implementation.
- Prefer verified relationships over guesses based on file names.
- Avoid exhaustive file inventories when a focused architecture explanation is sufficient.
